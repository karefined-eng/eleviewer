# EleViewer Python Application Rules & Directives

## Mandatory Context & Architecture Enforcement
Before creating or modifying any module in `eleviewer`, you MUST read and strictly adhere to `PROJECT_LOG.md` and `DEVELOPER_ONBOARDING.md`.

### Key Constraints:
1. **Zero Telemetry & PII Protection:** No analytics, no tracking, and no phone-home mechanisms. Unhandled exceptions and student feedback submitted via `feedback_dialog.py` MUST strip all user PII (such as Windows home directory paths via `os.path.expanduser("~")` -> `~`) before network transmission.
2. **Dynamic UI & Theme Consistency:** Do NOT hardcode hex color values in PySide6 UI modules. Crucially, do NOT use static, module-level imports for theme constants (e.g. `from theme import BRAND_PANEL`), as this locks components to the default theme on load. Always retrieve themes dynamically at runtime within widget initialization methods using `p = get_active_palette()` (from `theme.py`) to support seamless light/dark mode transitions. **Crucially, whenever you apply a custom `background` via `setStyleSheet()` on a widget, you MUST explicitly define `color: {p['BRAND_PRIMARY']};` (or a suitable contrast color) in the same stylesheet block. PySide6 will often strip inherited text colors when backgrounds are overridden, causing invisible text bugs in Light/Dark transitions.**
3. **Off-Thread Concurrency:** All network requests, file indexing, and auto-save operations MUST be executed on background `QThread` workers (e.g., `DraftWorker`, `VaultSearchWorker`, `FeedbackSubmitWorker`) to prevent UI freezes.
4. **Cognitive Load & Simplicity:** Preserve the lightweight, distraction-free "Sovereignty Workstation" philosophy. Avoid bloated toolbars or unnecessary configuration wizards. Maintain seamless support for the 4 Reflex keys (`Ctrl+Q`, `Alt+V`, `Ctrl+T`, `Ctrl+Shift+T`) and Universal TTS (`F9`).
5. **Atomic File Operations:** All settings and session saves MUST use atomic write patterns (`atomic_write`) to prevent 0-byte file corruption during sudden system shutdowns.
6. **Non-Blocking Thread Interruption:** When implementing cancellation or stop actions for background workers and COM/SAPI operations (e.g., `tts_engine.py`), never rely solely on queue messages or loop flags. Stop methods must immediately purge pending queue items and invoke native interruption APIs (e.g., `engine.stop()`) from any thread to abort blocking execution loops instantly.
7. **WebEngine & Popup Override Safety:** When overriding Qt WebEngine methods like `createWindow`, ensure all fallback window/tab creation methods accept keyword arguments (`url=`, `title=`) and always return a valid `QWebEngineView` pointer. If a tab cannot be created (e.g., feature disabled), the method must fall back to returning `self` (the originating `QWebEngineView`) to avoid a fatal `NOTREACHED` C++ exception when handling `target="_blank"` links.
8. **Logging & Diagnostics Persistence:** All production modules must implement context-aware logging via the `eleviewer.logger` utility, ensuring that critical state transitions and thread lifecycle events are captured in the local session log, while sensitive system paths are scrubbed for privacy.
9. **Tactile UI Responsive Feedback:** Destructive or active control buttons (like Stop or Cancel buttons in floating bars) must provide immediate tactile visual feedback using distinct icons and explicit `#ObjectName:hover` and `#ObjectName:pressed` stylesheet highlights.
10. **Search-Friendly Distribution Metadata:** Never use internal project jargon (e.g., "Sovereignty Workstation") in user-facing distribution metadata — including Windows PE file descriptions (`--windows-file-description`), WinGet manifest `ShortDescription`/`Description` fields, Inno Setup `AppName`, and GitHub release titles. Use plain, search-friendly terms that students and users would actually type (e.g., "Lightweight Document Viewer & Study Workspace"). The "Sovereignty Workstation" label is an internal design philosophy, not a public branding term.
11. **CI/CD Dynamic Versioning:** GitHub Actions release workflows MUST extract version numbers dynamically from the git tag (e.g., `github.ref_name`) instead of hardcoding them. Tag trigger patterns MUST use strict semver matching (e.g., `'v[0-9]+.[0-9]+.[0-9]+'`) to prevent accidental builds from pre-release, beta, or test tags. Installer filenames and release titles MUST use the extracted version variable, not literal strings.
12. **PowerShell Command Chaining:** This environment uses PowerShell as its default shell. Always use semicolons (`;`) to chain sequential commands, never `&&`. The `&&` operator is bash/cmd syntax and causes `InvalidEndOfLine` parse errors in PowerShell. Example: `git add .; git commit -m "msg"; git push origin main`
13. **Global Marketing Exclusivity (No UG Trojan Horse):** When optimizing SEO, website copy, or repository metadata, strictly target a global audience of students, researchers, and developers. Do NOT implement the "Localized UG Trojan Horse" strategy (e.g., targeting "University of Ghana" or "Abednego Lomazah" keywords) unless explicitly instructed for a specific regional campaign. The core `eleviewer-site` and `eleviewer` repository must remain universally applicable.
14. **Per-User Installer Registry (HKCU, Never HKCR):** In Inno Setup scripts with `PrivilegesRequired=lowest` (per-user, no admin required), ALL `[Registry]` entries that would normally target `HKCR` (e.g., ProgID definitions, file extension associations, context menu shell verbs) MUST instead target `HKCU\Software\Classes\`. `HKCR` writes silently fail without error on standard student machines without admin rights — Inno Setup reports success but Windows discards the writes. The correct per-user equivalents are:
    - `HKCR\EleViewer.PDF\...` → `HKCU\Software\Classes\EleViewer.PDF\...`
    - `HKCR\*\shell\EleViewer\...` → `HKCU\Software\Classes\*\shell\EleViewer\...`
    - `HKCR\.pdf\OpenWithProgids\...` → `HKCU\Software\Classes\.pdf\OpenWithProgids\...`
    Use only `OpenWithProgids` sub-key registration (not overwriting the `.ext` default value) for correct Windows 10/11 "Open With" dialog behavior without hostile file association takeover of other apps.
15. **Offline-First Resilience & Cloud Graceful Degradation:** EleViewer is an offline-first application designed for students. Any cloud or network-dependent enhancements (e.g., `edge-tts`, online dictionary lookups) MUST be implemented alongside a robust native, offline fallback (e.g., `pyttsx3`). Features should seamlessly degrade to the local implementation without crashing, stalling the UI, or requiring manual user intervention when the network is unavailable.
16. **Zero-Dependency Resourcefulness & Base64 UI Rendering:** Before reaching for heavy third-party binaries or new package dependencies to handle media extraction or format conversion (e.g., rendering slides or documents), ALWAYS investigate if the existing libraries (like `python-pptx`, `python-docx`, `openpyxl`) already expose raw binary data in memory. If so, extract the bytes natively, encode them to Base64, and embed them directly into PySide6 UI components (like `QTextBrowser`) using Data URIs (`<img src="data:image/png;base64,...">`). Avoid disk I/O and external executable dependencies at all costs to maintain the lightweight (<20MB) standalone footprint.
17. **Ponytail Debt Tracking:** Whenever applying a deliberate "ponytail" shortcut, deferral, or minimal implementation that may eventually hit a ceiling, you MUST leave an in-line comment prefixed with `ponytail:` (e.g., `# ponytail: [ceiling description] -> [upgrade path]`). This ensures the `ponytail-debt` skill can harvest all intentional tech debt into a centralized ledger, preventing deferrals from quietly becoming permanent. Do not leave this comment for standard library refactors or pure code deletions—only use it for temporary shortcuts or deferred flexibility.
18. **Module Export Contract Verification:** When modifying a module's public API surface — adding, removing, or renaming module-level constants, classes, or functions — always `grep` the codebase for all existing importers of that module and verify they still resolve. Never assume a name is internal just because it looks like one. The `TTS_AVAILABLE` crash was caused by `pdf_viewer.py` importing a name that `tts_engine.py` never actually defined. Run `grep -r "from <module> import" --include="*.py"` before committing any module-level refactor.
19. **User-Facing API Response Formatting:** Never display raw API response bodies (JSON, XML, plain wire-format strings) in `QMessageBox` or any user-facing dialog. Always parse structured responses (e.g., `json.loads()`) and render a human-friendly message. If parsing fails, fall back to a generic success/error message rather than showing raw protocol data. This applies to all network-dependent features, including `feedback_dialog.py`, update checkers, and any future API integrations.
20. **Native Windows MCI Audio Playback:** For playing generated audio files (such as TTS output), avoid adding third-party audio packages (e.g., `pygame`, `playsound`, `pydub`). Use native Windows Multimedia Command Interface via `ctypes.windll.winmm.mciSendStringW` with proper alias management (`open`, `play`, `stop`, `close`) to handle playback off-thread cleanly without extra binary footprint.
21. **QTextBrowser HTML Whitespace & Image Rendering Safeguard:** When rendering generated HTML documents or slide previews in `QTextBrowser`, do NOT apply `white-space: pre-wrap` CSS to root or parent containers holding embedded `<img>` tags. Qt's rich-text HTML engine misinterprets tag delimiters under `pre-wrap`, resulting in broken image icons or raw HTML output.
22. **Native Offline LaTeX Math & Markdown Preprocessing:** When adding math formulas ($...$ / $$...$$), task list checkboxes (`- [ ]`), or rich typography to document viewers, do NOT introduce heavy V8/JS engines or external web dependencies. Use lightweight Python regex preprocessors (`markdown_utils.py`) to convert LaTeX math symbols into Unicode/HTML tags (`<sup>`, `<sub>`, `<span>`) and expand `bleach` sanitizer whitelists to render rich content inside standard PySide6 `QTextBrowser` widgets natively.
23. **Dependency Injection via DI.py:** Always inject dependencies explicitly via `di.inject()` rather than using global imports or implicit singleton access. This ensures runtime configurability (e.g., swapping TTS engines) and simplifies testing. See `ui.py`, `settings_dialog.py`, and `autosaver.py` for correct patterns.
24. **Auto-Telemetry Crash Triage (GitHub CLI):** Because EleViewer suppresses terminal stack traces and automatically submits fatal crashes to GitHub Issues via telemetry, you cannot rely solely on the exit code of `python main.py` to verify stability. Before concluding any feature implementation, testing phase, or beginning compilation, you MUST run `gh issue list` via the CLI to check for and resolve any newly opened `[Bug] Feedback from App` issues. **When closing multiple issues, remember `gh issue close` only accepts a single issue number. Chain them in PowerShell (e.g., `gh issue close 49; gh issue close 50`).**
25. **The Chromium Tax & WebEngine Lazy-Loading:** To maintain the <100ms cold start, NEVER import `QtWebEngine` or `web_panel.py` at the module level. It must be strictly lazy-loaded inside the specific function that requires it (e.g., `Ctrl+T` activation). When lazy-loading, you must alias any global availability flags (e.g., `from web_panel import WEB_AVAILABLE as _WEB_AVAILABLE`) and safely update the global state (`global WEB_AVAILABLE; WEB_AVAILABLE = _WEB_AVAILABLE`) to prevent `UnboundLocalError` shadowing crashes.
    **Lazy-Scope Import Contamination:** Any helper function or constant used inside a lazy-loaded method (like `open_web_tab`) that already contains local imports and `global` statements must ALSO be imported locally within that method — even if it exists in the top-level module imports. Python's scoping makes top-level names unreliable inside functions with mixed `global`/local import statements. Import smoke tests will NOT catch this; the `NameError` only surfaces at runtime when the lazy path executes.
26. **Native Stdlib ZIP Parsing for OOXML (DOCX/PPTX) Fallbacks:** When creating or modifying document viewers for OpenXML formats (`.pptx`, `.docx`, `.xlsx`), do NOT rely solely on third-party packages (`python-pptx`, `python-docx`, `mammoth`). Always implement a zero-dependency standard library fallback using `zipfile` and `xml.etree.ElementTree` to parse paragraph text and Base64-encode image binaries from the zip archive (`word/media/`, `ppt/media/`) directly into HTML Data URIs (`<img src="data:image/...;base64,...">`). This guarantees 100% crash resilience and zero-dependency playback even when third-party libraries are uninstalled or fail.
27. **Natural Numeric Sorting for Sequenced Files:** When parsing, listing, or extracting sequentially numbered files (e.g., `slide1.xml`, `page2.png`, `part10.md`) from archives or directories, NEVER use standard string sorting (`sorted()`). Standard sorting is lexicographical and corrupts the order (e.g., 1, 10, 2). Always explicitly implement natural numeric sorting by extracting the integer from the filename (e.g., `key=lambda x: int(re.search(r'\d+', x).group())` or `.split()`) to guarantee strict sequential integrity.
28. **Safe Qt Exception Handling in Background Threads:** When implementing global error handlers (`sys.excepthook`) in PySide6, NEVER perform direct UI or clipboard operations (`QMessageBox`, `QApplication.clipboard()`) without first verifying thread affinity. `sys.excepthook` runs on the thread that threw the exception. If an exception originates from a background `QThread`, attempting to launch a dialog or access the clipboard directly will trigger a fatal COM OLE failure (`CoInitialize has not been called`). Either proxy the exception back to the main GUI thread using a dedicated `Signal` attached to a main thread worker, or use `QMetaObject.invokeMethod` with `Qt.QueuedConnection` to safely delegate the crash dialog creation to the main event loop.
29. **Flexible MainWindow Handler Signatures:** All public action methods on `MainWindow` (e.g. `open_file(self, file_path=None)`) MUST support optional positional/keyword arguments so they can be safely invoked from CLI arguments, IPC single-instance sockets, or background signals without `TypeError` crashes.
30. **Seamless Click-Outside Dialog Dismissal:** Quick-action dialogs (such as `VaultSearchDialog` and `QuickSwitcher`) MUST handle `QEvent.WindowDeactivate` inside their `event()` method to invoke `self.reject()`, allowing users to dismiss popups by clicking anywhere outside the dialog window.
31. **Mandatory Manual UI Action Validation:** When adding or modifying a UI action method (e.g. `_new_session` in `ui.py`) that is NOT covered by the standard regression suite, you MUST write and execute a temporary PySide6 test script to invoke the method directly before marking the issue resolved. This prevents silent runtime crashes like `AttributeError` from slipping into releases.
32. **Global Refactoring & Grep Truncation:** When renaming a method, changing a return type, or refactoring globally used constants (like theme variables), you MUST use `grep` to find and update all existing callers across the codebase. Crucially, if the `grep_search` tool returns a truncated result list ("more results not shown"), you must NEVER assume you have found all instances. You must refine the search query or search file-by-file to guarantee 100% coverage before considering the refactor complete.
33. **Context Directory Hygiene & Synthesis-Over-Dump Policy:** The `context/` directory must contain only curated, actionable synthesis documents — never raw AI conversation dumps, NotebookLM exports, or unstructured brainstorming transcripts. When ingesting external context (from NotebookLM, ChatGPT, Claude, or any AI conversation tool), always synthesize the actionable outcomes into a single structured document and delete the raw source files. Speculative feature wishes belong in GitHub Issues, not context files. Website-specific prompts or content belong in the `eleviewer-site` repository, not the desktop app's `context/` directory.
34. **Seamless PDF Touchpad Scrolling:** When implementing or modifying PDF viewers using `QPdfView`, always configure the viewer to use `QPdfView.PageMode.MultiPage` as the default. This ensures native, seamless continuous scrolling across page boundaries using a touchpad, rather than restricting users to arrow-key navigation under `SinglePage` mode.
35. **Modular & Movable UI Layouts:** When designing or modifying main application toolbars, menus, or side panels, prioritize modularity. Toolbar elements (such as Bookmarks, Web Panel, Open actions) should not be permanently anchored. Implement drag-and-drop or movable capabilities (similar to the implemented `QTabWidget` tabs or the Windows taskbar) to allow users to rearrange and customize their workspace tools to their ergonomic preference.
36. **Lazy-Scope Import Positioning Invariant:** When lazy-loading modules or UI widgets inside a method (e.g., `open_web_tab`), ALL local imports (`from PySide6.QtWidgets import ...`, `from theme import ...`) MUST be placed at the VERY FIRST lines of the function body before any logic or widget references. Placing local imports mid-function causes Python to treat the symbol as an unbound local throughout the entire function scope, resulting in fatal `UnboundLocalError` crashes at runtime when accessed above the import line.
37. **Left-Click System Tray Menus:** Standard Windows behavior maps system tray context menus to right-clicks. For EleViewer, strictly override this. Use the `QSystemTrayIcon.Trigger` event (single left-click) to instantly display the tray menu, reducing user friction.
38. **Modern Full-Tab Settings UI:** Never use blocking modal `QDialog` windows for the application Settings. Settings MUST be rendered as a full-width Editor Tab (e.g., `SettingsView`) containing a navigation sidebar (`QListWidget`) and a main content area (`QStackedWidget`). Individual settings must be wrapped in visually distinct UI Cards (`QFrame`), mimicking modern web aesthetics.
39. **Split-Panel Focus Modes:** When designing secondary side-by-side components (such as the Web Panel or Vault Explorer), always provide an "Expand/Maximize" toggle button on the panel's internal toolbar. This toggle must temporarily hide the opposing editor layouts (e.g., `self.main_splitter.hide()`) to instantly grant the panel full-window focus, saving the user from manually dragging splitters.
40. **QSyntaxHighlighter Font/Color Isolation:** Never set `color`, `font-size`, `font-family`, or `font-weight` inside a `QPlainTextEdit` or `QTextEdit` `setStyleSheet()` block that also has a `QSyntaxHighlighter` attached. Qt's stylesheet engine silently overrides all `QTextCharFormat` properties (bold, italic, foreground colors) applied by the highlighter, making syntax formatting invisible to the user. Instead, inject fonts natively via `widget.setFont(QFont("Consolas", 14))` and text colors via `palette.setColor(QPalette.Text, QColor(...)); widget.setPalette(palette)`. Limit the stylesheet to structural properties only (background, padding, border). After changing fonts or palettes, call `highlighter._setup_formats(); highlighter.rehighlight()` to rebuild format rules.
41. **Bundling Synchronization Contract:** Whenever new supported file formats are added to the application, or when bumping version numbers, you MUST synchronously update the installer script (`installer/installer.iss`) to register the new file associations. Additionally, you MUST update the Winget manifest (`winget/karefined-eng.EleViewer.installer.yaml` and `.locale.en-US.yaml`) to reflect any feature additions, hash changes, or file modifications. Never treat the Python code as the sole source of truth for a feature release.
